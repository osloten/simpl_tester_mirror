# simpl_tester

Это тестировщик, созданый в первую очередь для проверки решения олимпиад по информатике, конкретно по программированию. Он умеет запускать исполняемые файлы и .py программы без сторонних библиотек (только стандартные библиотеки Python). Если вы пишите не на Python (C, C++, Go, Java, Rust), то надо скомпилировать через компиляторы (GCC, Clang, gc, Javac, Rustc) в бинарный файл и только потом запускать тестер

## Быстрый старт

```bash
git clone https://codeberg.org/oslot/simpl_tester.git
cd simpl_tester
uv sync
```

*или*

Скачайте архив с последним [Релизом](https://codeberg.org/oslot/simpl_tester/releases)

Так вы попадёте в основную папку с проектом, далее нужно скачать папки problems/ для нужных олимпиад, решать задачи в соответствии с условием и для проверки нужно поместить скрипт (или бинарный файл) запускаете скрипт через `uv run main.py` или (если не используете uv) `python main.py`, далее же всё легко и интуитивно

## Олимпиады

Задачи и тесты хранятся отдельно, в репозитории
[simpl_tester-olympiads](https://codeberg.org/oslot/olympiads),
и скачиваются одной командой:

```bash
uv run main.py --fetch
```

Это скачает все олимпиады указанные в olympiads.json
Если же вы хотите скачать какую либо олимпиаду еденично, то можете ввести:

```bash
uv run main.py --fetch название_олимпиады
```

## Создание собственных проблем (так называются понятный для программы файлы из папки problems, где находятся input и output для программ)

Для создания своей проблемы, нужно создавать в папке problems/*название олимпиады* файлы с названием в виде номера задачи и раширением .in или .out (для stdin и stdout соответственно). Данные хранятся в виде чисел или строк, порядок данных по строкам совпадает с порядком проверок (тобеж input для первой проверки находится на строке 1 в .in, значит output лежит на той же строке, но в .out файлах). К примеру, нужно сделать программу где на вход подаётся число, а возвращается оно в удвоеном виде (как в примере из репозитория), значит в .in будет выглядеть как значения на вход ([пример](./problems/to/1.in)), а .out будет содержать удвоеные значения ([пример](./problems/to/1.out)).
Таким образом можно приспособить любые задачи, и проверка будет идти с любым колличеством этих самых значений (но не балуйтесь с этим, 10 проверок должно быть достаточно). Для уточнения, теперь каждое значение передаётся через перенос строки, соответственно выводится оно должно тоже через него, учитывайте этот факт при написании своих решений задач

## Листы с заданиями

Хранятся в формате .md в папке tasks/ и имеют структуру, описаную в to.md

### Структура листа

Название должно быть таким же, как и название олимпиады. В начале идёт frontmatter в YAML, выделяется тремя тире сверху и снизу, содержит название олимпиады, какой это этап, год, ссылка на первоисточник и язык (это чисто для человека, программе это ни к чему). Далее едёт номер задачи (заголовком h2) *название по желанию*, и потом идут методанные по задаче в виде переменных типа **строка** (номер, *заголовок*, **лимит по времени исполнения**, и по желанию можно ввести stdin и stdout, но это и так стандартизировано, так что можно обойтись). Потом идёт текст задачи (перед ним надпись Условие заголовком h3), форматы входных и выходных данных (заголовки также h3) и между задачами разделение чертой через 3 тире. **ТАКЖЕ ВАЖНО, ПЕРЕД КАЖДОЙ ПЕРЕМЕННОЙ ВВОДИТЬ МЕТАСЛОВО meta:, ТАК КАК ОНО В ПОСЛЕДСТВИИ БУДЕТ ИСПОЛЬЗОВАТЬСЯ ДЛЯ БОЛЕЕ КОРРЕКТНОЙ ОБРАБОТКИ ПРОГРАММОЙ И НУЖНО ДЛЯ ОТДЕЛЕНИЯ ТЕКСТА ОТ ПЕРЕМЕННЫХ!**
